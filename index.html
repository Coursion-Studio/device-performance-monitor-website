Twelve live metrics, one app at a time

Pick the platform, the device and the app inside the window. Nothing is hard-coded to one project, and every number is the device's own.

  • Memory & CPU All platforms

    Total footprint, the share resident in RAM, per-process CPU and a thread count that surfaces leaks the moment it stops coming back down.

  • Frames & jank All platforms

    Frame rate, janky-frame share and frame-time percentiles, so a stutter is a spike you can point at rather than a feeling.

  • AI session analysis Your own key

    Claude, GPT or Gemini reads the run and answers in words: what leaked, which screen did it, what to change — with a per-screen diagnosis.

  • Screen tracking Native & RN

    Every reading is stamped with the screen the app was showing — Activities, Compose routes or React Navigation — so a spike maps to a route.

  • Baselines & alerts All platforms

    Save a known-good run and diff against it, or set a ceiling per metric and get a notification the moment a live reading crosses it.

  • Exports that travel All platforms

    CSV, JSON, Markdown, a shareable HTML report, or the charts as PNG and PDF for a ticket nobody has to re-run.

One window, the whole session.

Live tiles for the numbers that matter, a chart per metric banded by screen, markers you drop as you go, and a warning the moment the app starts climbing. Stop the session and it is saved, ready to reopen, diff against a baseline or hand to an AI.

What it measures

The same app, headless.

Install dpm on your PATH with one button. Give it a device and a package and it samples without a window, writes JSON, and exits non-zero when a budget is blown — so CI fails the build and an AI agent reads the numbers back to you.

This terminal answers real commands. Try dpm devices, dpm apps, dpm record or dpm help.

Hand it to Claude Code, Codex or Cursor.

The app ships ready-made prompts that already name your device and package. The agent runs dpm on your Mac and reads the JSON back to you — or you drop the whole reference into your repo's AGENTS.md and it needs no prompt at all.

  • Check a flow for leaks

    “Record com.example.app for 120 seconds while I use it, then tell me whether memory kept climbing, with the average and peak.”

  • Compare before and after

    “Record my branch, stash the changes, rebuild, record again, and give me a table of memory and CPU with the difference.”

  • Gate the build

    “Add a CI step that runs dpm record with a 400 MB budget, fails the job on exit 1 and uploads the JSON.”

Seven tools around the monitor

Live monitoring is the headline. The Home launcher opens the rest — each one a full tool, not a tab.

  • App bundle size

    Where an .apk, .aab or .ipa spends its bytes — breakdown, treemap, the real per-device download, and a file-by-file compare of two builds.

  • Startup timing

    Cold and warm launch times, batched across runs and charted with averages, so a regression in first-frame time is obvious.

  • Cold-start benchmark

    Android cold start the way Macrobenchmark measures it — over adb, no Gradle module — reported as a distribution with a stable-vs-noisy read.

  • Log viewer

    Live logcat, a simulator's log or an iPhone's syslog — filtered, coloured by severity, following the tail, saved to a file.

  • Battery & thermal

    Charge, temperature and thermal state over a session, with a derived drain rate and two runs compared side by side.

  • Screenshot & record

    A device screenshot or a screen recording, previewed then saved, without leaving the app.

  • Native SwiftUINo Electron, no web views. It feels like macOS because it is.
  • Runs on your MacReadings never leave your machine. AI analysis is opt-in, with your own API key.
  • Signed end to endDeveloper ID signed, notarized by Apple, with signed automatic updates.
